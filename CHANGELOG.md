# Changelog

Все значимые изменения в проекте sysflex документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
проект придерживается [Семантического версионирования](https://semver.org/lang/ru/).

## [2.0.0] — 2026-09-12

Первый стабильный релиз. Основное изменение — режим работы по умолчанию.

### Изменено (важно, ломает совместимость со скриптами)
- **Поведение по умолчанию теперь живое**: запуск `sysflex` без аргументов
  открывает постоянно обновляющийся дашборд (как раньше `--live`) и
  работает, пока пользователь сам не остановит его через Ctrl+C.
- Старое поведение (разовый вывод полной информации и выход) теперь
  доступно через новый флаг `--once`. Если вы используете `sysflex` в
  скриптах и ожидаете разового вывода — добавьте `--once`
  (например: `sysflex --once --json`).
- `--short`, `--json`, `--game` и `--bench` по-прежнему разовые и не
  требуют `--once`.

### Прочее
- Внутренние блоки расширенной диагностики переименованы в понятные
  разделы («Расширенная диагностика», «Диагностика ядра и подсистем»)
  вместо служебных маркетинговых названий из истории разработки.
- Обновлена документация (README, CHANGELOG) под релизную версию 2.0.0.

## [1.3.0] — 2026-09-12

### Добавлено — второй пакет метрик диагностики + обновление live-режима
Ещё 30 метрик из `/proc`/`/sys` (итого 60 дополнительных метрик поверх
базовых), полностью встроенных во все режимы вывода (обычный, `--json`,
`--live`) — ничего не осталось "закопанным":

31. CPU iowait %
32. CPU steal %
33. CPU softirq %
34. Загрузка по каждому ядру отдельно
35. Архитектура CPU (x86_64/aarch64/...)
36. BogoMIPS
37. Slab (память ядра)
38. PageTables
39. Committed_AS
40. Active(anon)
41. Shmem
42. Mapped
43. KernelStack
44. Диск: операций в очереди прямо сейчас
45-46. Суммарно прочитано/записано на диск с момента загрузки
47. Количество блочных устройств
48. Суммарное время занятости диска
49. Открытых UDP-сокетов
50-51. Суммарный трафик (rx/tx) с момента загрузки
52-53. Ошибки/потери пакетов (rx/tx)
54. IP шлюза по умолчанию
55. Суммарное число потоков всех процессов
56. Число уникальных пользователей, владеющих процессами
57. Загруженных модулей ядра
58. Clocksource
59. Init-система (имя процесса PID 1)
60. Kernel cmdline (кратко)

### Изменено
- Интервал обновления `--live` по умолчанию — 1 секунда (было 2), чтобы
  нагрузочная статистика (CPU, per-core, диск, сеть) обновлялась чаще
  "из коробки" без явного `--interval 1`.
- В `--live` добавлена вторая строка с метриками из пакета 2 (iowait,
  steal, очередь диска, число потоков, загрузка по ядрам) — все
  пересчитываются на каждом кадре из реальных данных `/proc`.

## [1.2.0] — 2026-09-12

### Добавлено — 30 метрик расширенной диагностики
Новый блок метрик, читаемых напрямую из `/proc`/`/sys` на каждом снимке
(в `--live` реально пересчитывается каждый интервал, а не является
статичным «один раз при старте»):

1. Модель CPU
2. Размер кэша CPU
3. CPU governor (scaling_governor)
4. Переключений контекста в секунду
5. Прерываний в секунду
6. Форков процессов в секунду
7. Процессов в состоянии running
8. Процессов, заблокированных на I/O (blocked)
9. Количество процессов-зомби
10. Доступная энтропия ядра
11. MemAvailable
12. Buffers
13. Cached
14. Dirty pages (ожидающие записи на диск)
15-16. HugePages (всего / свободно)
17-18. IOPS диска (чтение / запись операций в секунду)
19. Тип корневой файловой системы
20. Количество смонтированных «реальных» файловых систем
21-22. TCP-соединения (ESTABLISHED / LISTEN)
23. Количество сетевых интерфейсов
24. DNS-серверы из resolv.conf
25. Скорость вентилятора (RPM), если есть датчик
26. Максимальная температура среди всех hwmon-датчиков
27-28. Открытые файловые дескрипторы / системный лимит
29. Системная локаль (LANG)
30. Часовой пояс системы

Все 30 метрик добавлены в полный вывод (новый блок расширенной диагностики), в JSON
(`"extras": {...}`) и частично (ctxt/intr/forks/IOPS/TCP/FD) — в
компактную строку `--live` режима, которая обновляется каждый кадр и
наглядно показывает, что статистика живая, а не подставная.

## [1.1.0] — 2026-09-12

### Добавлено
- Опция `--top N` — настраиваемое количество процессов в топе (было жёстко
  зашито 5).
- Опция `--timeout N` — настраиваемый таймаут для внешних команд.
- Опция `--no-ascii` — отключение ASCII-арт логотипа.
- Поддержка конфиг-файла `~/.config/sysflex/config` (или `$SYSFLEX_CONFIG`)
  с настройками по умолчанию; аргументы командной строки имеют приоритет.
- 2 новые темы оформления: solarized, tokyonight.

### Исправлено
- Плагины, найденные одновременно в нескольких каталогах (например,
  локальный `./plugins` и системный `/usr/local/share/sysflex/plugins`
  после `install.sh`), больше не запускаются и не выводятся дважды —
  теперь они дедуплицируются по имени файла.
- Все вызовы внешних команд (`docker`, `bluetoothctl`, `playerctl` и др.)
  теперь ограничены таймаутом — недоступный демон/сервис больше не вешает
  запуск sysflex навсегда.
- Устранены все предупреждения компилятора при сборке с `-Wall -Wextra`
  (неинициализированные поля `Theme`, атрибуты `decltype(&pclose)`).

## [1.0.0] — 2026-09-12

### Добавлено
- Первый публичный релиз sysflex.
- Полный сбор системной информации: CPU (загрузка, частота, температура,
  load average, температуры по ядрам), RAM, диск (место + I/O), сеть,
  GPU (NVIDIA/AMD), батарея, swap, аптайм, процессы, shell/terminal,
  OS/ядро/hostname, Docker, Git-ветка, музыкальный плеер (playerctl),
  USB и Bluetooth устройства, inode, залогиненные пользователи, текущее время.
- Расчёт health score (0-100) на основе ключевых метрик системы.
- Режимы работы: нормальный, `--live`, `--short`, `--json`, `--game`, `--bench`.
- 5 тем оформления: default, dracula, nord, catppuccin, gruvbox.
- ASCII-арт логотипы для Debian, Ubuntu, Arch, Fedora и общий логотип.
- Спарклайн-графики истории значений для живого режима.
- Система плагинов (bash-скрипты в каталоге `plugins/`).
- Примеры плагинов: crypto.sh, weather.sh, uptime.sh.
- Модульные тесты для utils, sparkline и system_info.
- CI/CD через GitHub Actions (сборка + тесты на Ubuntu).
- Скрипты install.sh / uninstall.sh для установки в систему.

### Технические детали
- Стандарт C++17, без внешних зависимостей (только стандартная библиотека + pthread).
- Вся системная информация читается напрямую из `/proc`, `/sys` и через
  вызовы стандартных Linux-утилит (nvidia-smi, lsusb, docker, git, playerctl и т.д.).
